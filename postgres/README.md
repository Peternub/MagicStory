# PostgreSQL MagicStory

Каталог содержит миграции для собственного PostgreSQL без служебных схем Supabase.

Порядок переноса:

1. Создать таблицы миграцией `001_create_tables.sql`.
2. Загрузить данные из схемы `public` Supabase.
3. Добавить триггеры и функции приложения миграцией
   `002_create_functions_and_triggers.sql`.
4. Сравнить количество записей в исходной и новой базах.
5. Только после проверки переключить backend на новую базу.

Старая рабочая база использует более раннюю схему. При переносе статусы,
параметры серий и тарифов преобразуются функциями из
`lib/migration/legacy-supabase.ts`.

Миграция `001_create_tables.sql` намеренно не создаёт внешний ключ
`profiles.id -> auth.users.id`: авторизация на первом этапе остаётся в Supabase,
а пользовательские данные уже хранятся в российском PostgreSQL.

Порт `5432` не публикуется. Backend подключается к базе через
`127.0.0.1` на том же сервере.
